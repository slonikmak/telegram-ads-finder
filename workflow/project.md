# Telegram Advanced Search

## Назначение проекта
Сервис предназначен для автоматического мониторинга выбранных Telegram-каналов через пользовательский аккаунт (MTProto). Приложение анализирует входящие сообщения, извлекает из них параметры (наименование товара, цену, валюту) и проверяет их на соответствие заранее определенному набору правил-фильтров. В случае совпадения пользователь получает мгновенное уведомление.

## Основные сценарии
1. Периодический polling новых сообщений из заданного списка Telegram-каналов с сохранением прогресса.
2. Парсинг сырого текста и извлечение ключевых характеристик.
3. Сопоставление извлеченных данных с правилами (поиск по ключевым словам, вхождение в ценовые диапазоны).
4. Отправка уведомлений о найденных совпадениях через Telegram Bot API.
5. Сохранение истории сообщений и данных о совпадениях в локальную базу данных.

## Ключевые компоненты
- **Telegram Client:** Использует `GramJS` для подключения к Telegram API в качестве обычного пользователя (работа по MTProto). Периодически опрашивает каналы и группы через `iterMessages`.
- **Poller:** Polling-оркестратор, циклически обходящий настроенные источники и передающий новые сообщения в pipeline обработки. Сохраняет checkpoint (последний обработанный `message_id`) для каждого источника.
- **Match Engine:** Гибкая система фильтрации и валидации, определяющая, подходит ли сообщение под настроенные критериры.
- **Bot Notifier:** Компонент для диспетчеризации уведомлений через выделенного бота.
- **Хранилище:** Локальная база данных `SQLite` (через обертку `Better-SQLite3`) для сохранения состояния.

## Технические решения
На текущий момент в проекте используется:
- **Runtime:** Node.js 20+
- **Конфигурация:** YAML (для настройки правил, подписок и каналов)
- **Логирование:** `pino`

## Известные ограничения и слабые места
- *На текущий момент известно*, что система работает через клиентский MTProto (userbot-подход). Это накладывает строгие ограничения по лимитам со стороны антиспам-систем Telegram.
- Корректность парсинга сильно зависит от структуры оригинального сообщения: нестандартный формат цен или валют в канале может приводить к пропускам данных.
- Возможны проблемы с отображением UTF-8 (эмодзи и спецсимволов) при выводе логов в стандартную консоль Windows.

## Открытые вопросы и точки роста
- Требует уточнения масштабируемость Match Engine при сильном увеличении библиотеки правил и каналов контента.
- Требует уточнения стратегия поведения системы (graceful degradation) при бане пользовательской сессии или временной блокировке на получение обновлений (FloodWait).
