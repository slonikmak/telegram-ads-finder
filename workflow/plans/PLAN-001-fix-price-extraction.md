# PLAN-001: Реализация извлечения всех цен и исправление парсинга

## Related Issue
ISS-003

## Related Req
REQ-001

## Objective
Переписать логику извлечения цен (`src/price.js`) и интегрировать массив цен в логику поиска объявлений.

## Approach
Выбранный подход:
- Заменить `regex.exec` цикл на `text.matchAll(regex)` для извлечения всех вхождений.
- Использовать более надежный парсер чисел.
- В `src/index.js` объект `msgEntity` будет хранить массив найденных цен, или `price_value` будет хранить первую найденную цену, а для матчинга передавать полный список. Чтобы не ломать структуру БД сходу, в `messages` сохранять первую цену (или null), а в `matcher.js` производить проверку по всем найденным ценам. В идеале `insertMatch` должен сохранять в базу именно ту цену, которая спровоцировала совпадение.

## Steps
1. Подключить тестовый раннер (встроенный `node:test` или `jest`).
2. Написать базовые unit-тесты для функции `extractPrices` с известными краевыми случаями.
3. Обновить `src/price.js`, реализовать новую логику: `extractPrices(text, fxConfig)`.
4. Добиться зеленого статуса unit-тестов.
5. Обновить `src/index.js`, чтобы получать из `extractPrices` массив цен, брать первую как `price_value` для БД (backward compatibility). 
6. Передать массив цен в `matcher.js` и настроить проверку `some()`.
7. Обновить возвращаемое значение из `matcher.js` (возвращать `matchedPrice` и `matchedCurrency` именно те, которые подошли). 

## Risks
Основные риски:
- Можно сломать текущий парсинг цен, который "раз в год, но работал".
- Изменение структуры `msgEntity` может сломать интеграцию с `db.js`.

## Validation
Как будет проверяться результат:
- Успешное выполнение написанных unit-тестов (`npm test`).
- Локальная проверка на живых данных (через логи).
