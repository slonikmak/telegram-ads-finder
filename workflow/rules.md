# Workflow Rules

## 1. Общие правила

- Любая новая работа начинается с issue.
- Документы workflow должны быть короткими, ясными и полезными в ежедневной работе.
- Не выдумывать факты, которых нет в коде, проекте или согласованном контексте.
- Не превращать маленький проект в тяжелый процесс.

## 2. Источники истины

- `project.md` отражает текущее состояние проекта на обзорном уровне.
- `issue` фиксирует контекст, цель и результат конкретной работы.
- `req` используется только если нужно зафиксировать или изменить поведение системы.
- `plan` используется только если задача требует явной декомпозиции.
- `research` используется только для изучения и выбора решения.

## 3. Когда что создавать

### Создавать только issue, если:
_Шаблон:_ [`issues/ISS-template.md`](issues/ISS-template.md)

- задача маленькая;
- задача понятная;
- поведение системы не меняется;
- не нужен отдельный план.

### Добавлять req, если:
_Шаблон:_ [`reqs/REQ-template.md`](reqs/REQ-template.md)

- вводится новая функциональность;
- меняется ожидаемое поведение;
- есть риск двусмысленности в том, что именно нужно сделать.

### Добавлять plan, если:
_Шаблон:_ [`plans/PLAN-template.md`](plans/PLAN-template.md)

- задача состоит из нескольких шагов;
- есть заметный риск или зависимость;
- нужен контроль прогресса.

### Добавлять research, если:
_Шаблон:_ [`research/RES-template.md`](research/RES-template.md)

- сначала нужно изучить варианты;
- решение пока не очевидно;
- надо сравнить инструменты, подходы или архитектурные варианты.

## 4. Правила обновления документов

- Если меняется текущее решение, сначала фиксируется issue, затем обновляется актуальная документация.
- Обзорные документы не должны содержать устаревшую информацию как будто она все еще актуальна.
- Если информация устарела, она должна быть обновлена или удалена.
- Не смешивать текущие факты, будущие идеи и исторические заметки в одном абзаце без явного разделения.

## 5. Правила для коммитов

- Каждый meaningful commit по возможности должен ссылаться на ID issue.
- Для крупных изменений коммит может также ссылаться на req.

Примеры:
- `ISS-012 fix empty state text`
- `ISS-021 add validation for settings form`
- `ISS-034 REQ-005 implement export flow`

## 6. Правило минимальности

- Если сомневаешься, начинай с issue.
- Остальные документы добавляй только когда без них уже неудобно.
